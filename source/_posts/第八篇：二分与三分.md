[上一篇](/2026/11/19/simulation-enumeration-greedy/)说，枚举是把候选方案挨个检查一遍。这个办法很可靠，但如果候选答案有一万亿个呢？

这时候要问的不是“怎么把枚举写快一点”，而是：**检查一个位置之后，我能不能确定一整段都不用再看？**

- 如果候选项能排成一段不满足、一段满足，我们可以用**二分**找分界线。
- 如果要在一个先降后升的区间里找最低点，可以比较两个位置的值，用**三分**缩小范围。

> 本文的 4 份完整程序可分别用 C++11 或更新的标准编译运行。样例均为自拟；数组下标从 `0` 开始。

------

### 一、二分查找：找到第一个大于等于目标的位置

**问题：** 给定一个非降序数组和整数 `target`，输出第一个满足 `a[i] >= target` 的下标。如果不存在，输出 `n`。第一行输入 `n` 和 `target`，第二行输入 `n` 个整数；`0 <= n <= 100000`，数值的绝对值不超过 `10^9`。

当数组是 `1 2 2 2 5 8`、目标是 `2` 时，符合条件的有好几个，我们要的是**第一个**，不能随便命中一个就结束：

```plaintext
下标：    0  1  2  3  4  5
数组：    1  2  2  2  5  8
大于等于：否 是 是 是 是 是
```

#### 1. 先说清楚 `left` 和 `right` 的含义

下面的写法从 `left = 0, right = n` 开始。每一轮都保证：**第一个达标下标（没有就用 `n` 表示）一定在闭区间 `[left, right]` 内。** 但程序只在 `left < right` 时取中点，此时总有 `mid < right <= n`，不会访问 `a[n]`。

- `a[mid] < target`：非降序保证 `mid` 及其左侧都不满足，令 `left = mid + 1`。
- `a[mid] >= target`：第一个达标下标不可能在 `mid` 右侧，但 `mid` 自己还可能是答案，令 `right = mid`。
- `left == right`：只剩一个候选下标，直接输出它。

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    vector<int> values(n);
    for (int& value : values) cin >> value;

    int left = 0, right = n;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (values[mid] >= target) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    cout << left << '\n';
}
```

输入：

```plaintext
6 2
1 2 2 2 5 8
```

输出：

```plaintext
1
```

这个样例依次把候选下标缩到 `[0, 3]`、`[0, 1]`、`[1, 1]`。如果目标比所有元素都大，最后会得到 `n`；如果数组为空，则一开始 `left == right == 0`，一次也不用访问数组。

每轮把候选范围缩小到约一半，查找用 `O(log(n + 1))` 次比较和 `O(1)` 额外空间；完整程序还需要 `O(n)` 时间和 `O(n)` 空间读入并存储数组。

#### 2. 标准库里的两条边界

对于同一个非降序 `vector`，`<algorithm>` 里已经有对应的工具：

- `lower_bound(values.begin(), values.end(), target)`：第一个 `>= target` 的位置。
- `upper_bound(values.begin(), values.end(), target)`：第一个 `> target` 的位置。

它们返回迭代器；找不到时返回 `values.end()`，不能解引用。将迭代器减去 `values.begin()` 就得到下标。所有等于 `target` 的元素恰好在两条边界之间，所以用后一条边界减前一条就得到出现次数。上面的数组里，两条边界对应下标 `1` 和 `4`，`2` 一共出现 `3` 次。

### 二、二分答案：最小需要多大的容量？

**问题：** 有 `n` 件物品按固定顺序排好，每件重量为正整数。它们要分到至多 `maxDays` 天运完，每天运走一段连续的物品，不能拆分，也不能改顺序。求每天的载重上限最小是多少。

第一行输入 `n` 和 `maxDays`，第二行输入 `n` 个重量。约定 `1 <= maxDays <= n <= 100000`，单件重量不超过 `10^9`。

#### 1. 把“求最小值”改成“这个值行不行”

给定一个容量 `capacity`，能不能在规定天数内运完？如果做得到，换成更大的容量，照着同一套方案运就行。因此，从小到大排列容量，判定的结果只能从“不行”变成“可以”，不会再变回去：

```plaintext
不行 不行 …… 不行 | 可以 可以 …… 可以
                    ↑ 最小可行容量
```

左端取最重的单件重量，因为更小的容量连那一件都装不下。右端取所有重量之和，因为这个容量一天就能运完。

#### 2. 给定容量时，为什么可以尽量装满当天？

从第一件开始，当前这一天还能装就继续装，放不下下一件时才开新的一天。这里和上一篇有关：**外层用二分找答案，内层用贪心判断答案。**

第一天，贪心运到了容量允许的最远位置。假设前 `d` 天结束后，贪心运的件数至少和另一套方案一样多。到了第 `d + 1` 天，如果贪心还没有到达对方这一天的终点，它要补运的那段只是对方当天运过的一段后缀，重量不会更大，一定装得下。于是这一天结束后，贪心仍至少和对方一样远。

一天一天推下去：如果有方案能在规定天数内运完，贪心也能；如果连贪心都不行，就可以判定这个容量太小。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

bool canShip(const vector<long long>& weights, int maxDays, long long capacity) {
    int days = 1;
    long long load = 0;
    for (long long weight : weights) {
        if (load + weight > capacity) {
            ++days;
            load = 0;
            if (days > maxDays) return false;
        }
        load += weight;
    }
    return true;
}

int main() {
    int n, maxDays;
    cin >> n >> maxDays;
    vector<long long> weights(n);
    long long left = 0, right = 0;
    for (long long& weight : weights) {
        cin >> weight;
        left = max(left, weight);
        right += weight;
    }

    while (left < right) {
        long long mid = left + (right - left) / 2;
        if (canShip(weights, maxDays, mid)) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    cout << left << '\n';
}
```

输入：

```plaintext
5 3
3 2 2 4 1
```

输出：

```plaintext
5
```

容量为 `5` 时，贪心装成 `[3, 2] | [2] | [4, 1]`，只用 `3` 天；容量为 `4` 时，需要 `4` 天。装得恰好等于容量是允许的，所以换天条件用 `>`，而不是 `>=`。判定函数只接收不小于最重物品的容量；要脱离这个前提单独复用它，就得先拒绝装不下的单件物品。

设总重量为 `S`，每次判定最多扫 `n` 件，最多判定 `O(log(S + 1))` 次，总时间为 `O(n log(S + 1))`，存储用 `O(n)` 空间。`S` 最大可达 `10^14`，所以容量、总重量和当天载重都用 `long long`。

### 三、实数三分：比较两个位置，留下最低点

二分答案需要的是一条单调的真假分界线。但如果函数先下降、再上升，函数值本身并不单调。光算出一个 `f(mid)`，通常还不知道该往哪边走。

假设函数在最小点左侧严格下降、右侧严格上升，最小点也允许在端点。我们在当前区间 `[left, right]` 内取靠左的 `mid1` 和靠右的 `mid2`，把区间大致分成三段：

- 如果 `f(mid1) < f(mid2)`，最低点不可能在 `mid2` 右边。如果它在那里，两个点都还在下降段，应当是左边更高才对。令 `right = mid2`。
- 如果 `f(mid1) > f(mid2)`，同理最低点不可能在 `mid1` 左边。令 `left = mid1`。
- 如果两点的函数值相等，在精确计算下，最低点一定在两点之间。这份代码把相等与第一个分支合并，仍然保留最低点。

每一轮不是留下三分之一，而是留下大约**三分之二**。如果求的是先升后降的**最大值**，比较方向反过来即可。

**问题：** 在 `0 <= x <= 100` 的实数区间内，找出让 `(x - a)² + (x - b)²` 最小的 `x`。输入两个绝对值不超过 `200` 的整数 `a, b`，输出一个近似位置，允许绝对误差 `10^-5`。

把式子配方，可得 `2(x - (a+b)/2)² + (a-b)²/2`。所以它在 `(a+b)/2` 左侧递减、右侧递增；如果这个点落在区间外，最优点就是区间中较近的端点。这题本可以用公式直接求解，这里故意用三分，把公式留作检验程序的参照。

```cpp
#include <iomanip>
#include <iostream>
using namespace std;

long double cost(long double position, long double a, long double b) {
    long double distanceA = position - a;
    long double distanceB = position - b;
    return distanceA * distanceA + distanceB * distanceB;
}

int main() {
    long double a, b;
    cin >> a >> b;
    long double left = 0, right = 100;
    for (int step = 0; step < 80; ++step) {
        long double third = (right - left) / 3;
        long double mid1 = left + third;
        long double mid2 = right - third;
        if (cost(mid1, a, b) <= cost(mid2, a, b)) {
            right = mid2;
        } else {
            left = mid1;
        }
    }
    cout << fixed << setprecision(6) << (left + right) / 2 << '\n';
}
```

输入：

```plaintext
20 70
```

一种符合误差要求的输出：

```plaintext
45.000000
```

理想情况下，迭代 `k` 次后，区间长度约为初始长度乘以 `(2/3)^k`。本题固定迭代 `80` 次，每轮计算两次代价，额外空间为 `O(1)`。实际精度还取决于浮点运算和输出位数；不能因为多迭代了几轮，就认为结果一定多对几位小数。换一道题时，要重新看初始区间、允许误差以及函数值的计算是否稳定。

### 四、整数三分：区间够小时，直接枚举

**问题：** 给定 `n` 个位置的代价，保证序列在最小值段之前严格递减，在最小值段之后严格递增；最小值可以连续出现多次。有些段可以为空。输出最左的最小值下标。

第一行输入 `n`，第二行输入 `n` 个代价。约定 `1 <= n <= 100000`，代价的绝对值不超过 `10^9`。

当 `right - left < 3` 时，`(right - left) / 3` 会得到 `0`，更新可能原地不动。因此只在至少有 `4` 个候选位置时三分，剩下至多 `3` 个时直接枚举。相等时保留左边：如果最左的最小值还在 `mid2` 右侧，两个三分点都在严格下降段上，函数值不可能相等。最后从左向右扫描，只在发现更小的代价时更新答案，就能保留最左下标。

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> costs(n);
    for (int& cost : costs) cin >> cost;

    int left = 0, right = n - 1;
    while (right - left >= 3) {
        int third = (right - left) / 3;
        int mid1 = left + third;
        int mid2 = right - third;
        if (costs[mid1] <= costs[mid2]) {
            right = mid2;
        } else {
            left = mid1;
        }
    }

    int best = left;
    for (int i = left + 1; i <= right; ++i) {
        if (costs[i] < costs[best]) best = i;
    }
    cout << best << '\n';
}
```

输入：

```plaintext
7
9 6 4 4 4 7 10
```

输出：

```plaintext
2
```

查找用 `O(log(n + 1))` 次比较，额外空间为 `O(1)`；完整程序还包含读入数组的 `O(n)` 时间和空间。如果代价是按下标现算的，就应该把每次求值的开销算进总复杂度。

**同一道题也能二分。** 最左最小值之前，`costs[i] > costs[i + 1]`；从最左最小值起，`costs[i] <= costs[i + 1]`。在 `[0, n - 1]` 上二分第一个满足后一条件的下标，把 `n - 1` 当作找不到时的答案。依旧用 `left < right` 循环，就不会访问 `costs[n]`。这里二分的是**相邻代价的比较结果**，不是代价本身。

注意：如果允许在下坡中途出现平台，就不能照搬这些等号规则。试试 `9 8 8 8 8 1 2`：第一次取的两个三分点代价都是 `8`，按上述代码保留左侧就会丢掉真正的最小值 `1`。所以题目只说“先不增、后不减”时，还要看具体条件，不能直接套这份模板。

### 五、动手前，把这几个问题答清楚

1. **我在搜什么？** 数组下标、答案大小，还是函数的自变量？选错变量，比较结果可能根本不单调。
2. **为什么能丢掉那一段？** 二分答案要证明判定结果只换一次方向；三分要检查目标函数的形状和相等时的处理。“中间看起来比较好”不够。
3. **边界也被保留了吗？** `right = mid` 是因为 `mid` 可能是答案；`left = mid + 1` 是因为已排除 `mid`。找“最后一个真”时，不要照抄更新规则，要重新写清楚保留的区间。
4. **循环一定会结束吗？** 只剩两个整数候选时，向下取整的中点等于左端。此时如果写 `left = mid`，区间就可能不动。整数三分也要检查两点何时不再严格位于区间内部。
5. **复杂度和数值范围算全了吗？** 二分次数少不代表判定便宜；容量、乘积和函数值可能超出 `int`。求中点的 `left + (right - left) / 2` 也要求差值能放进所用类型，本文的整数区间都满足这一点。

## 最后，去练习吧

1. **查找边界：** 在 `2 2 4 7` 中，分别求目标为 `1`、`2`、`3`、`8` 时的 `lower_bound` 和 `upper_bound` 下标。哪个结果能直接说明目标不存在？
2. **反向二分：** 有三段长度为 `8 7 6` 的绳子，要剪出至少 `5` 段等长的整数长度绳子，允许有剩余。每小段最长能是多少？先写出判定式，再判断要找第一个真还是最后一个真。
3. **装载边界：** 用同一组重量 `3 2 2 4 1`，求只给 `1` 天、给 `5` 天时的最小容量。与搜索区间的两个端点有什么关系？
4. **实数端点：** 给实数三分程序输入 `-20 10` 和 `100 140`，分别拿输出与配方法的结果比较。
5. **整数平台：** 分别测试 `7`、`8 6 3` 和 `4 4 4 4`，并把整数三分改成比较相邻代价的二分。两种做法是否给出相同的最左下标？

<details>
<summary>自测提示与参考结果</summary>

- **查找边界：** 两种边界的下标分别是 `(0, 0)`、`(0, 2)`、`(2, 2)`、`(4, 4)`。两条边界相同就说明没有等于目标的元素；只看 `lower_bound` 时，要先排除 `end()`，再核对找到的元素是否等于目标。
- **剪绳子：** 给定正整数长度 `length`，计算 `8 / length + 7 / length + 6 / length`（整数除法），判断是否至少为 `5`。要找最后一个真。长度 `3` 能剪出 `6` 段，长度 `4` 只能剪出 `4` 段，因此答案是 `3`。
- **装载：** 只给 `1` 天时要装下全部重量，答案 `12`；给 `5` 天时可以一件一天，答案 `4`。恰好分别是初始的右端点与左端点。
- **实数：** 无约束最低点分别是 `-5` 和 `120`，限制在 `[0, 100]` 内后，答案分别是 `0` 和 `100`。
- **整数：** 两种写法都应分别得到 `0`、`2`、`0`。

</details>
