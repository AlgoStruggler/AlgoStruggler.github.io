在前面四篇里，我们写的所有代码都堆在 `main` 函数里。这在几十行的时候还能忍受，但一旦代码变多，你就会发现一个问题：**同样的逻辑，你写了不下于三遍。**

比如你要在三个不同的地方计算两个数的最大值，你就得把 `if (a > b)` 写三遍。这不仅烦，而且容易写错，更难维护。

这时候就需要**函数**了。

函数可以理解成一个**带名字的代码块**。你把一段逻辑封装进去，给它起个名字，然后想用的时候喊它一声就行。

> 不严谨但好懂的理解：函数就像你厨房里的一个调料盒——里面装好了调好的酱汁，做菜的时候舀一勺就行，不用每次重新调。你用的时候不用关心它里面具体怎么调的，只要知道它能给菜加什么味就行。

### 一、函数的定义与调用

一个完整的函数包含四个部分：

```cpp
返回类型 函数名(参数列表) {
    // 函数体
    return 返回值;
}
```

写一个最简单的函数——**计算两个整数的最大值**：

```cpp
int max(int a, int b) {
    if (a > b) {
        return a;
    } else {
        return b;
    }
}
```

然后你就可以在 `main` 里这样调用它：

```cpp
int x = 5, y = 7;
int result = max(x, y); // result = 7
cout << result << endl;
```

每次要比较两个数，直接喊 `max(x, y)` 就行，不用再写一遍 `if` 了。

> **注意**：函数必须**先定义，后调用**。如果你把 `max` 的定义写在 `main` 后面，编译器会不认识它。解决方法有两个：一是把函数定义放在 `main` 前面；二是在 `main` 前面加一个**函数声明**（把函数头复制一份加个分号放上面）。

### 二、参数传递

C++ 里的参数默认是**值传递**——函数拿到的是**实参的副本——形参**，不是实参本身。**你在函数里修改参数，不影响外面的变量：**

```cpp
void change(int a) {
    a = 10; // 改的是副本
}

int main() {
    int x = 5;
    change(x);
    cout << x << endl; // 还是 5，不是 10
    return 0;
}
```

如果你希望函数能修改外面的变量，可以用**引用传递**（在参数类型后面加 `&`）：

```cpp
void change(int &a) {
    a = 10; // 改的是原变量
}

int main() {
    int x = 5;
    change(x);
    cout << x << endl; // 输出 10
    return 0;
}
```

引用在竞赛中很常用，尤其是传递 `string` 或结构体等稍大的数据时，可以避免拷贝的开销。后面我们会反复用到它。

### 三、返回值

函数用 `return` 返回结果。一旦执行到 `return`，函数立刻结束，后面的代码不再执行。

```cpp
int check(int a) {
    if (a > 0) {
        return 1; // 返回 1，函数结束
    }
    return 0; // 如果前面没返回，执行这里
}
```

**返回类型必须和 `return` 的值的类型匹配**。如果函数不需要返回值，用 `void`：

```cpp
void printHello() {
    cout << "Hello" << endl;
    // return ;
    // 没有 return，或者写 return ;（不带值）
}
```

### 四、变量的作用域

在函数内部定义的变量，只在这个函数里有效，外面访问不到：

```cpp
void func() {
    int x = 10; // x 只在 func 里存在
}

int main() {
    cout << x; // ❌ 编译错误：x 未定义
    return 0;
}
```

不同函数里的同名变量互不干扰：

```cpp
void funcA() {
    int x = 1;
    cout << x; // 输出 1
}

void funcB() {
    int x = 2;
    cout << x; // 输出 2
}
```

如果你需要多个函数共享一个变量，可以把它定义在所有函数**外面**（叫**全局变量**）：

cpp

```cpp
int global_x = 0; // 全局变量，所有函数都能访问

void add() {
    global_x ++;
}

int main() {
    add();
    cout << global_x; // 输出 1
    return 0;
}
```

在 ACM 里，如果数组开得很大（比如 10⁶ 以上），通常把它定义为全局变量，避免栈溢出的风险。

### 五、函数的声明与定义分离

如果你想把函数定义放在 `main` 后面，需要在 `main` 之前先**声明**函数：

```cpp
#include <iostream>
using namespace std;

int max(int a, int b);  // 函数声明（结尾有分号）

int main() {
    cout << max(5, 7) << endl;
    return 0;
}

int max(int a, int b) { // 函数定义
    return a > b ? a : b;
}
```

在多人协作的大型项目里，声明通常放在头文件（`.h`）里，定义放在源文件（`.cpp`）里。不过在 OJ 刷题的单文件场景下，只要满足“先声明后使用”就行，怎么放差别不大。

### 六、递归——函数调用自己

**递归就是函数调用自己**。它适合解决“可以拆分成同类子问题”的问题。

比如**计算阶乘**：`n! = n * (n - 1)!`，这就是一个典型的递归定义。

```cpp
int factorial(int n) {
    if (n <= 1) return 1; // 终止条件
    return n * factorial(n - 1); // 自己调用自己
}
```

递归必须有两个关键部分：

- **终止条件**：必须有一个“停下来”的条件，不然会无限调用下去（最终栈溢出）
- **递推关系**：当前问题的解 = 用更小的问题的解来构造

希望读者可以体会这种状态转移的思想，想要得到 `factorial(n)` 只需要知道 `factorial(n - 1)` ，以此类推。知道初始条件就可以地推出终值。

再比如**斐波那契数列**：`fib(n) = fib(n-1) + fib(n-2)`

```c++
int fib(int n) {
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);
}
```

斐波那契数列也是标准的递推，我们可以使用状态转移方程 `fib[i] = fib[i - 1] + fib[i - 2]` 去实现，也可以用上面的函数的递归去实现。

### 七、递归的代价

递归的写法很优雅，但**它是有代价的**。

每次函数调用，系统都要在内存里保存当前函数的局部变量、返回地址等信息（这叫“调用栈”），等递归返回后再恢复。这意味着：

- 递归比循环**慢**（函数调用有额外开销）
- 递归层数太深会**爆栈**（栈内存耗尽）

比如 `fib(100)` 如果写成递归，不仅慢得无法接受，而且会栈溢出。

> **什么时候用递归？** 当问题的结构本身就是递归的（比如树、图的遍历），用递归写最简单；否则，优先用循环。在 ACM 里，能用循环解决的就不要用递归，除非递归的深度可控（比如不超过几百层）。

### 八、常见错误与注意事项

1. **函数定义在调用之后，且没有提前声明**

```cpp
int main() {
    cout << add(1, 2); // ❌ 编译器不认识 add，应该先声明
}
int add(int a, int b) {
    return a + b;
}
```

2. **返回值类型不匹配**

```cpp
int getValue() {
    return 3.14; // ❌ 返回 double，但函数类型是 int
}
```

3. **递归没有终止条件**

```cpp
int f(int n) {
    return f(n - 1); // ❌ 没有终止条件，永远不结束
}
```

4. **全局变量被无意中修改**

全局变量虽然方便，但一旦在多个函数里被修改，调试时会很难追踪。尽量少用全局变量，除非是大数组这类必须用的场景。
