前面几篇里，我们学会了顺序、选择和循环，认识了数组、字符串、函数、递归，也知道了栈、队列和堆可以怎样组织数据。

但真正打开一道题，你可能还是会愣住：**这些工具我都认识，可是第一步该干什么？**

这一篇，我们开始讨论“怎么想”。先从三种常见思路说起：**模拟、枚举和贪心**。

- 题目告诉你一套规则，就把过程一步一步做出来，这是**模拟**。
- 答案可能藏在一些候选方案里，就挨个检查，这是**枚举**。
- 希望每一步直接做出一个选择，而且这个选择不会妨碍得到最优答案，这是**贪心**。

它们并不是三个互不相干的盒子。一道题可能先枚举一个起点，再模拟后面的过程；也可能先排序，再按贪心策略选择，最后用模拟维护状态。

> 本文的 7 份完整程序可以分别复制运行，使用 C++11 或更新的标准。样例均为本文自拟；输入满足各题约定。除特别说明外，下标从 `0` 开始。

------

### 零、先看数据范围：你的办法跑得动吗？

上一篇认识了 `O(1)`、`O(n)` 和 `O(log n)`。这次再加几个常见记号：

| 复杂度 | 大致在做什么 | 当 `n = 1000` 时的数量级参考 |
| --- | --- | --- |
| `O(n)` | 扫描一遍数据 | 一千 |
| `O(n log n)` | 常见的比较排序 | 一万左右 |
| `O(n²)` | 检查两两组合 | 一百万 |
| `O(n³)` | 枚举三个独立变量 | 十亿 |
| `O(2^n)` | 检查所有子集 | 已经极大，通常不可行 |

表中的数字只是帮助理解增长速度，**不是精确的运行次数，也不是通过时限的保证**。真实耗时还与常数、语言、机器、输入输出和时限有关。

比如，两个循环都跑 `n` 次，里面只有常数次操作，总时间通常是 `O(n²)`；如果第二层只从 `i + 1` 开始，总组合数约为一半，数量级仍是 `O(n²)`。

反过来，不能只数代码里有几层循环。两个循环先后各扫一遍数组，合起来仍是 `O(n)`；外层每次把范围缩小一半，也未必是 `O(n)`。

**先写出操作量，再代入数据范围估算。** 很多时候，不是你不会做，而是你想到了一个办法，却还没判断它适不适合这道题。

### 一、模拟：把题目中的规则翻译成程序

模拟很像照着菜谱做饭。题目说先放什么、什么时候翻面、满足什么条件才能出锅，你就按顺序执行。

听起来简单，但规则一多，最容易出问题的恰恰是“先后顺序”和“边界条件”。

#### 1. 先找状态，再写变化

拿到模拟题，可以先在纸上回答四个问题：

1. **状态是什么？** 比如余额、位置、方向、当前时间。
2. **初始状态是什么？** 从多少钱、哪个格子、什么方向开始。
3. **一次操作怎样改变状态？** 先增加还是先扣除，失败后是否变化。
4. **什么时候结束，输出什么？** 输出最终状态、失败位置，还是过程统计。

变量不只是为了装输入，也是在表示“这个过程走到这里，世界是什么样”。

#### 2. 例子一：每天结余多少钱？

**问题：** 一开始余额为 `0`。连续 `n` 天，每天先收到收入，再支付当天支出。如果当天余额不足以支付支出，立即输出 `FAIL d`，其中 `d` 是第一次失败的天数；如果全部支付成功，输出最后的余额。

约定 `0 <= n <= 100000`，每天收入和支出都是 `0` 到 `10^9` 的整数；每天的数据按“收入、支出”的顺序输入。

先手算一遍：

| 天数 | 收入 | 支出 | 支付前余额 | 支付后余额 |
| --- | --- | --- | --- | --- |
| 1 | 100 | 30 | 100 | 70 |
| 2 | 20 | 80 | 90 | 10 |
| 3 | 50 | 40 | 60 | 20 |

状态只有一个：`balance`，表示**已经完成的那些天结束后，还剩多少钱**。

每一天依次做三件事：加上收入，判断是否够付，扣掉支出。

```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long balance = 0;

    for (int day = 1; day <= n; ++day) {
        long long income, expense;
        cin >> income >> expense;
        balance += income;

        if (balance < expense) {
            cout << "FAIL " << day << '\n';
            return 0;
        }
        balance -= expense;
    }

    cout << balance << '\n';
    return 0;
}
```

输入：

```plaintext
3
100 30
20 80
50 40
```

输出：

```plaintext
20
```

注意两个细节：

- `balance == expense` 时可以恰好付清，所以失败条件是 `<`，不是 `<=`。
- 每天的数虽然不超过 `10^9`，余额却可能累积到 `10^14`，因此使用 `long long`。

最多处理 `n` 天，时间复杂度为 `O(n)`，额外空间为 `O(1)`。本程序只有一组数据，确定失败后直接结束；如果题目有多组数据，就要考虑是否仍需读完当前组剩下的输入。

#### 3. 例子二：在地图上移动

**问题：** 给定 `n` 行 `m` 列的地图，`.` 表示空地，`#` 表示障碍。机器人从指定格子出发，执行一个由 `U`、`D`、`L`、`R` 组成的指令串，分别表示上、下、左、右。

如果下一步会越界或撞上障碍，忽略这条指令，位置保持不变。输出最终的行号和列号。

约定 `1 <= n, m <= 1000`，指令串长度为 `1` 到 `100000`；输入、输出坐标均从 `1` 开始，起点保证在空地上。程序内部转成从 `0` 开始，行号向下增大，列号向右增大。

这里很适合用**方向数组**：

```plaintext
方向编号：  0       1       2       3
指令：      U       D       L       R
行变化：   -1      +1       0       0
列变化：    0       0      -1      +1
```

先计算候选位置，确认合法后再更新当前位置。这样就不用“先走过去，出错了再退回来”。

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<string> grid(n);
    for (int i = 0; i < n; ++i) cin >> grid[i];

    int r, c;
    string commands;
    cin >> r >> c >> commands;
    --r;
    --c;

    const string directions = "UDLR";
    const int dr[4] = {-1, 1, 0, 0};
    const int dc[4] = {0, 0, -1, 1};

    for (char command : commands) {
        int d = static_cast<int>(directions.find(command));
        int nr = r + dr[d];
        int nc = c + dc[d];

        if (nr >= 0 && nr < n && nc >= 0 && nc < m
            && grid[nr][nc] != '#') {
            r = nr;
            c = nc;
        }
    }

    cout << r + 1 << " " << c + 1 << '\n';
    return 0;
}
```

输入：

```plaintext
3 4
....
.#..
....
2 1
URRDDL
```

输出：

```plaintext
3 2
```

从 `(2, 1)` 向上到 `(1, 1)`，向右两次到 `(1, 3)`，向下两次到 `(3, 3)`，最后向左到 `(3, 2)`。

`directions.find(command)` 找到指令在字符串中的位置。这里输入保证只有四种合法指令；如果允许其他字符，就必须先处理“没有找到”的情况，再访问方向数组。

代码先判断边界，再读取 `grid[nr][nc]`。C++ 的 `&&` 会从左往右判断，前面为假就不再计算后面，这叫**短路求值**。不能把数组访问放到边界检查前面。

设指令长度为 `k`，读地图需要 `O(nm)`，执行指令需要 `O(k)`，总时间为 `O(nm + k)`；保存地图和指令需要 `O(nm + k)` 空间。

#### 4. 模拟不一定要把每个细节都做一遍

假设题目说“时钟前进十亿秒”，不代表必须循环十亿次。若只关心最终时刻，可以把当前时刻换算成秒，加上偏移后对一天的秒数取模。

**模拟要求遵守规则，但不要求照搬现实中的每一个动作。** 能合并的重复过程可以合并；但如果中途还要判断余额不足、碰撞或事件触发，就不能未经分析直接跳到终点。

### 二、枚举：把所有可能的候选方案检查一遍

假设你忘记了一个三位密码，但知道每位都是数字。最直接的办法是什么？

从 `000` 到 `999` 逐个试。

这就是枚举的味道：**只要候选范围有限，而且每个候选都能判断，就可以逐个检查。**

枚举不是“瞎猜”。一个可靠的枚举要说明三件事：

- **范围完整**：正确答案一定在里面。
- **检查正确**：什么条件代表这个候选可行。
- **计数准确**：求方案数时，不能把同一个方案重复算进去。

#### 1. 例子一：不同价格的三种笔

**问题：** A 笔每支 `3` 元，B 笔每支 `2` 元，C 笔每支 `1` 元。恰好买 `n` 支，恰好花 `m` 元，三种笔都可以买 `0` 支。问有多少种购买方案。

约定 `0 <= n <= 1000`，`0 <= m <= 3000`。只按三种笔各买多少支区分方案，不考虑购买顺序。

设三种笔各买 `a`、`b`、`c` 支，条件为：

```plaintext
a + b + c = n
3a + 2b + c = m
a、b、c 都是非负整数
```

最直接可以写三层循环，分别枚举 `a`、`b`、`c`。不过，**知道了前两个，第三个就已经确定了**：`c = n - a - b`。

所以只需要两层循环：

```cpp
#include <iostream>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    long long answer = 0;

    for (int a = 0; a <= n; ++a) {
        for (int b = 0; b <= n - a; ++b) {
            int c = n - a - b;
            if (3 * a + 2 * b + c == m) {
                ++answer;
            }
        }
    }

    cout << answer << '\n';
    return 0;
}
```

输入：

```plaintext
4 8
```

输出：

```plaintext
3
```

三个方案分别是 `(a, b, c) = (0, 4, 0)`、`(1, 2, 1)`、`(2, 0, 2)`。

为什么不会漏？任何合法方案都有 `0 <= a <= n`、`0 <= b <= n - a`，因此一定会被这两层循环走到。为什么不会重复？每一组 `(a, b)` 只出现一次，而 `c` 又由它们唯一确定。

循环次数为 `(n + 1)(n + 2) / 2`，时间复杂度是 `O(n²)`，额外空间是 `O(1)`。

> **还可以继续减少枚举。** 把 `c` 代入金额条件，可得 `2a + b = m - n`。只枚举 `a`，令 `b = m - n - 2a`，再计算 `c`，检查二者非负即可，时间可降到 `O(n)`。上面的两层写法用于展示“用约束消掉一个变量”的过程；数据更大时，应继续利用条件。

#### 2. 例子二：两数之和，数的是哪一种方案？

**问题：** 给定 `n` 个整数和目标值 `target`，统计满足 `i < j` 且 `a[i] + a[j] == target` 的下标对数量。

约定 `0 <= n <= 3000`，数组元素和目标值都在 `-10^9` 到 `10^9` 之间。**相同数值出现在不同位置，算不同元素。**

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    long long target;
    cin >> n >> target;
    vector<long long> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    long long answer = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (a[i] + a[j] == target) ++answer;
        }
    }

    cout << answer << '\n';
    return 0;
}
```

输入：

```plaintext
4 4
1 3 1 3
```

输出：

```plaintext
4
```

四个下标对为 `(0, 1)`、`(0, 3)`、`(1, 2)`、`(2, 3)`。

为什么让 `j` 从 `i + 1` 开始？这样既不会把一个元素和自己配对，也不会把 `(0, 1)` 和 `(1, 0)` 算成两个方案。

如果题目要的是“不同的数值组合”，这个样例就只有 `{1, 3}` 一种。**循环怎么写，取决于题目究竟把什么当作一个方案。**

一共检查 `n(n - 1) / 2` 对，时间复杂度为 `O(n²)`。保存数组需要 `O(n)` 空间，数组以外只用常数空间。

#### 3. 怎样让枚举少做一些工作？

可以从三个方向考虑：

1. **减少变量。** 总数已知时，最后一个数量常常能直接计算。
2. **缩小范围。** 买笔时已经用了 `a` 支，`b` 就不必再枚举到 `n`。
3. **提前排除。** 如果能证明当前选择不可能扩展成合法答案，就不继续检查它后面的情况。这常被称为“剪枝”。

但提前结束需要条件。例如按价格升序检查时，预算不够买当前商品，也买不起之后更贵的商品，可以 `break`；在无序数组中遇到一个太贵的商品，却不能据此停止。

枚举也常被用作小规模的参照程序：先写一个容易确认正确、但只能处理小数据的版本，再拿它去检查更快的算法。后面我们会用这个办法验证贪心。

### 三、贪心：每一步都选一个“现在最好”的方案

你有 `10` 元钱，面前有几件商品，想尽可能多买几件。很自然会想到：**先买便宜的。**

这种每一步按照某个规则直接选择的思路，就是贪心。

贪心通常不会展开所有后续分支再比较，而是选定后继续往下走。因此，它最需要回答的问题是：

**现在看起来最好，会不会让后面付出更大的代价？**

#### 1. 先看一个失败的贪心：总拿最大的硬币

硬币面值为 `1`、`3`、`4`，每种数量无限。要凑出 `6`，并且让硬币数量最少。

如果每次都拿不超过剩余金额的最大面值：

```plaintext
先拿 4，还剩 2
再拿 1，还剩 1
再拿 1，结束
共 3 枚
```

但 `3 + 3 = 6`，只需要 `2` 枚。

这说明“每次拿最大的”对这组面值不能保证最优。**贪心策略必须结合具体条件证明，不能因为某种货币体系里常用，就推广到任意面值。**

找到了一个反例，就足以否定一个声称“总是正确”的策略；跑过很多样例，也只能增加信心，不能替代证明。

#### 2. 例子一：有限预算，最多买几件？

**问题：** 有 `n` 件商品，每件只能买一次，每件对答案的贡献都是“买到一件”。给定预算 `budget`，问最多能买几件。

约定 `0 <= n <= 100000`，`0 <= budget <= 10^14`，每件价格为 `1` 到 `10^9` 的整数；没有搭售、折扣或必须购买的商品。

策略：**按价格从小到大排序，依次购买，直到下一件买不起。**

为什么可以这样选？把所有价格排序为 `p[0] <= p[1] <= ...`。对于任何一个买了 `k` 件的方案，把它的价格也从小到大排列，它的第 `i` 件价格不会小于全部商品中第 `i` 便宜的价格。

因此，**最便宜的 `k` 件，其总价不大于任意其他 `k` 件的总价**。

于是，只要最便宜的 `k` 件都超出预算，其他任何 `k` 件也买不起；最便宜的前 `k` 件能买下，就是一个实际可行的方案。两边合起来，得到的数量就是最大值。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    long long budget;
    cin >> n >> budget;
    vector<long long> price(n);
    for (int i = 0; i < n; ++i) cin >> price[i];
    sort(price.begin(), price.end());

    int answer = 0;
    for (long long p : price) {
        if (p > budget) break;
        budget -= p;
        ++answer;
    }

    cout << answer << '\n';
    return 0;
}
```

输入：

```plaintext
5 10
6 2 4 1 3
```

输出：

```plaintext
4
```

排序后为 `1 2 3 4 6`，前四件恰好花掉 `10` 元。排序需要 `O(n log n)`，扫描需要 `O(n)`，总时间为 `O(n log n)`。价格数组占 `O(n)` 空间，排序自身还需要实现相关的辅助空间。

这里的条件很关键：**每件商品的贡献相同，目标是数量最大。** 如果每件有不同价值，目标变成总价值最大，“最便宜优先”就不一定成立，那是另一个问题。

#### 3. 例子二：最多参加多少场活动？

**问题：** 有 `n` 场活动，每场活动有开始时间 `start`、结束时间 `finish`。同一时间只能参加一场，活动必须从头到尾参加，问最多能参加几场。

约定 `0 <= n <= 100000`，`0 <= start < finish <= 10^9`。时间段采用半开区间 `[start, finish)`，所以一场在 `3` 时刻结束，另一场在 `3` 时刻开始，可以连续参加。

你可能会想到几个策略：最早开始、持续时间最短、最早结束。先拿反例试试前两个。

- **最早开始：** 活动为 `[0, 10)`、`[1, 2)`、`[2, 3)`、`[3, 4)`。先选最早开始的，只能参加 `1` 场；后三场可以参加 `3` 场。
- **持续时间最短：** 活动为 `[0, 4)`、`[4, 8)`、`[3, 5)`。先选最短的 `[3, 5)`，就无法再参加另外两场；但前两场可以连续参加，共 `2` 场。

正确的策略是：**每次从与已选活动兼容的活动里，选结束最早的一场。**

直观上，越早结束，就越早把时间留给后面的活动。这个直觉还可以写成证明。

#### 4. 用“交换”解释为什么正确

设贪心选择的第一场是 `G`。从一个最多场数的方案中，取它的第一场 `A`。

因为 `G` 在所有活动中结束最早，所以：

```plaintext
finish(G) <= finish(A)
```

把最优方案里的 `A` 替换成 `G`，后面的活动仍然能参加：它们原本都在 `A` 结束后开始，自然也在 `G` 结束后开始。

这样替换后，场数没有减少，仍是最优方案。也就是说，**至少存在一个最优方案，它的第一步与贪心相同**。

选完 `G` 以后，只考虑在它结束后开始的活动，剩下的问题与原问题具有相同形式；再重复相同理由，就能一步一步构造出最优答案。

这种“把最优方案的一部分换成贪心选择，答案不会变差”的方法，叫**交换论证**。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

struct Activity {
    int start;
    int finish;
};

bool earlierFinish(const Activity& a, const Activity& b) {
    if (a.finish != b.finish) return a.finish < b.finish;
    return a.start < b.start;
}

int main() {
    int n;
    cin >> n;
    vector<Activity> activities(n);
    for (int i = 0; i < n; ++i) {
        cin >> activities[i].start >> activities[i].finish;
    }
    sort(activities.begin(), activities.end(), earlierFinish);

    int answer = 0;
    int lastFinish = 0;  // 本题所有开始时间均非负
    for (const Activity& activity : activities) {
        if (activity.start >= lastFinish) {
            ++answer;
            lastFinish = activity.finish;
        }
    }

    cout << answer << '\n';
    return 0;
}
```

输入：

```plaintext
5
0 10
1 2
2 3
3 4
1 4
```

输出：

```plaintext
3
```

按结束时间排序后，依次选择 `[1, 2)`、`[2, 3)`、`[3, 4)`。

时间复杂度为 `O(n log n)`，活动数组占 `O(n)` 空间，扫描只用常数额外空间；排序自身另有实现相关的辅助空间。

这里还要留意：

- 能首尾相接，所以判断是 `start >= lastFinish`。如果题目要求两场之间留出休息时间，条件要跟着改变。
- 结束时间相同的活动，任取一个兼容者都不会影响后续可用时间。代码用开始时间打破平局，方便固定顺序。
- `sort` 的比较函数要使用严格比较，不能写成 `a.finish <= b.finish`，否则连元素与自身比较都会返回真，不满足排序要求。
- `lastFinish = 0` 依赖于开始时间非负。若允许负时间，可以用“是否已选过活动”的标记单独处理第一场。
- 如果每场活动的收益不同，目标改为总收益最大，这个按场数证明的策略就不能直接套用。

#### 5. 例子三：合并代价最小，为什么用小根堆？

上一篇认识了堆，现在让它来维护贪心选择。

**问题：** 有 `n` 堆石子，每次可以任意选择两堆合并，代价等于两堆重量之和。重复合并，直到只剩一堆，求总代价的最小值。

约定 `0 <= n <= 100000`，每堆重量为 `1` 到 `10^9` 的整数；`n <= 1` 时不需要合并，代价为 `0`。**可以任意选两堆，没有“只能合并相邻堆”的限制。**

比如 `1 2 3`：

```plaintext
先合并 1 和 2：代价 3，剩下 3、3
再合并 3 和 3：代价 6
总代价：3 + 6 = 9

如果先合并 2 和 3：代价 5，剩下 1、5
再合并 1 和 5：代价 6
总代价：5 + 6 = 11
```

策略是：**每次取当前最小的两堆合并，把新堆放回，再取最小的两堆。**

“放回”很重要，新堆接下来仍要参与比较，所以只在开头排序一次、然后相邻配对，并不能实现这个策略。小根堆正好支持反复取最小值和插入新值。

为什么先合并最小的两堆？可以把一个完整合并过程画成二叉树：原来的石子堆是叶子，每次合并产生一个父节点，最后的大堆是根。

```plaintext
        6
       / \
      3   3（原堆）
     / \
    1   2
```

每堆原始重量会在它每次向上参与合并时贡献一次代价，因此：**总代价 = 每个原始重量乘以它到根的边数，再全部相加。** 上图就是 `1×2 + 2×2 + 3×1 = 9`。

在一棵最优合并树中，取一对深度最大的兄弟叶子。这样的兄弟一定存在：最深叶子的兄弟若还带着孩子，就会产生更深的叶子。

把最小的两个重量交换到这两个位置，不会增加总代价。原因是，把较小重量 `x` 放到更深的 `d2` 层，把较大重量 `y` 放到更浅的 `d1` 层，其中 `x <= y`、`d1 <= d2`，代价变化为：

```plaintext
交换后 - 交换前
= (x*d2 + y*d1) - (x*d1 + y*d2)
= (y - x) * (d1 - d2)
<= 0
```

所以至少有一棵最优树，让最小的两堆成为兄弟，可以先合并。把它们缩成重量为两者之和的一堆后，余下仍是同一种问题；它的最优代价加上这一次合并的代价，就是原问题的最优代价。

这就给“每次取最小两堆”提供了依据。初学时先记住树里“越早合并，重量就可能被重复计费越多”的关系，再慢慢消化这个证明。

```cpp
#include <functional>
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    priority_queue<long long, vector<long long>, greater<long long>> heap;
    for (int i = 0; i < n; ++i) {
        long long weight;
        cin >> weight;
        heap.push(weight);
    }

    long long answer = 0;
    while (heap.size() > 1) {
        long long a = heap.top();
        heap.pop();
        long long b = heap.top();
        heap.pop();
        long long merged = a + b;
        answer += merged;
        heap.push(merged);
    }

    cout << answer << '\n';
    return 0;
}
```

输入：

```plaintext
3
1 2 3
```

输出：

```plaintext
9
```

每次合并使堆数减少 `1`，`n >= 1` 时恰好合并 `n - 1` 次。每次进行常数次堆操作，总时间为 `O(n log n)`，空间为 `O(n)`。

合并后的重量和累计代价都使用 `long long`。按本题范围，总重量不超过 `10^14`。考虑一种按层两两配对、落单就留到下一层的合法方案：每层每份重量至多计费一次，至多 `17` 层即可合完 `100000` 堆。最优代价不会比这个方案更大，所以不超过 `17×10^14`，在 `long long` 范围内。

如果要求**只能合并相邻两堆**，上面的交换就未必保持合法，小根堆策略也不能直接套用。例如 `1 100 1` 中，两堆最小的 `1` 并不相邻；本题条件与那种题目不同。

### 四、把三种思路放在一起看

| 思路 | 核心动作 | 先检查什么 |
| --- | --- | --- |
| 模拟 | 按规则更新状态 | 初值、顺序、边界 |
| 枚举 | 逐个检查候选 | 范围、判定、重数 |
| 贪心 | 按策略作出选择 | 选择的依据、剩余问题 |

模拟要问“这一步之后，状态是什么”；枚举要问“所有候选都检查到了吗”；贪心则要问“这个选择为什么能保留最优答案”。目标或约束改变以后，都要重新回答这些问题。

它们也不对应固定的复杂度。模拟可能很慢，枚举也可以通过约束变得很快；贪心常常还需要排序或数据结构配合。

做题时可以按这样的顺序想：

1. **说清输出。** 是最终状态、方案数量、可行性，还是最优值？
2. **写出最直接的办法。** 能否照规则做，或者把候选全部检查一遍？
3. **估算规模。** 这个办法在最大输入上需要多少工作？
4. **利用条件减少工作。** 少枚举一个变量、跳过无用状态，或者寻找可证明的选择规则。
5. **验证边界和理由。** 想找反例，再手算和运行代码。

别急着因为题目有“最大”“最小”就判定是贪心。枚举也能求最优值，后面要学的搜索、动态规划等方法同样能解决最优化问题。

### 五、怎样检查自己的贪心？

#### 1. 先造容易让策略为难的数据

如果策略是“先选最长”“先选最短”“先选最大”，就专门考虑：**这次占到的便宜，会不会挡住后面两个更合适的选择？**

活动选择里，一场很短但卡在两场之间的活动，就是针对“最短优先”的反例。

再检查相等、首尾相接、恰好用完、完全选不了、全部能选这些情况。边界经常比随机数据更快暴露错误。

#### 2. 用小规模枚举作参照

比如最多买商品，当 `n <= 15` 时，可以枚举每件商品“买或不买”的全部子集，计算总价和件数，取合法方案中的最大件数。

然后生成很多小数据：同一组输入，同时交给子集枚举和贪心程序；如果结果不同，就保留这组输入，手动追踪每一步。这种比较通常称为**对拍**。

活动选择也可以枚举所有子集，判断其中活动能否互不冲突，再取最多场数；合并石子可以在很小的 `n` 下枚举每一步选择的两堆，递归计算最小总代价。

这里枚举程序的价值，是帮助寻找反例和检查实现。**参照程序也可能写错，对拍通过也不是数学证明。** 它和正确性论证各自解决不同的问题，都值得做。

### 六、常见错误与注意事项

#### 1. 把题目没说的条件当作默认条件

坐标是否从 `1` 开始？同一时刻结束和开始是否冲突？商品能否重复买？两堆是否必须相邻？这些细节会改变模型，甚至改变算法。

先把约定写下来，再写程序。

#### 2. 状态已经改坏，才想起来检查

移动时先计算 `(nr, nc)`，合法后再更新；支付时先确认余额足够，再扣除。尽量让每次循环结束时，保存的状态都有清楚的含义。

如果多个对象要“同时更新”，也要区分旧状态和新状态，必要时另开一份数组。逐个原地修改，可能让后面的对象读到已经变化的数据，结果就不再是同时发生。

#### 3. 枚举范围多一点少一点都没关系

允许买 `0` 支，就要包含 `0`；允许恰好买 `n` 支，就要包含 `n`。是否重数也必须按题意判断，不能最后随便除以 `2`。

#### 4. 看到排序，就以为是贪心

排序只是工具。真正的策略是“按什么顺序做什么选择”，证明也要针对这个选择。

活动选择要按结束时间；买最多商品要按价格。这两个排序条件都来自目标和约束，不能互换。

#### 5. 单个输入不大，就放心用 `int`

求和、乘法、方案数和累计代价都可能远大于单个输入。使用更宽的类型时，还要让**运算本身**在宽类型里进行：例如两个 `int` 相乘后再赋给 `long long`，中间仍可能溢出；可写成 `1LL * a * b`。

但 `long long` 也不是无限大，仍需估算上界。

## 最后，去练习吧

先独立完成，再展开自测提示。每题都试着写一句话：**我的程序为什么没有漏掉答案，或者为什么可以这样选？**

1. **记账模拟：** 用本文第一份程序检查余额恰好付清、第一天失败、最后一天失败，以及 `n = 0`。再把规则改为“先支出、后收入”，看看样例结果是否改变。
2. **地图模拟：** 一行地图 `.#.`，从第 `1` 行第 `1` 列出发，执行 `RULD`，最终在哪里？再试试 `1×1` 地图的四个方向。
3. **减少枚举：** 把三种笔的程序改成只枚举 `a`，验证 `n = 4, m = 8`、`n = 0, m = 0` 和无解的 `n = 4, m = 13`。
4. **下标与数值：** 数组为 `2 2 2 2`，目标值为 `4`，有多少个下标对？如果统计不同数值组合，又有多少种？
5. **购买商品：** 预算为 `7`，价格为 `5 2 2 3`，最多买几件？写出一个达到答案的方案，并说明再多买一件为什么不行。
6. **活动选择：** 活动为 `[0, 2)`、`[2, 4)`、`[1, 3)`、`[4, 5)`、`[0, 5)`，求最多场数。如果改成“必须严格晚于上一场结束时刻才可开始”，结果会怎样？
7. **最小合并：** 重量为 `1 2 3 4`，手算小根堆每一步的内容及总代价；再测只有一堆和所有重量相等的情况。
8. **反例练习：** 给硬币面值 `1 3 4`，目标金额为 `6`，解释为什么“每次取最大面值”失败；再尝试给“活动收益最大时仍优先最早结束”造一个反例。

<details>
<summary>自测提示与参考结果</summary>

- **记账：** `1` 天、收入支出同为 `5` 时输出 `0`；`1` 天、收入 `0` 支出 `1` 时输出 `FAIL 1`；`2` 天依次为 `5 5`、`0 1` 时输出 `FAIL 2`；`n = 0` 时输出 `0`。若先支出，正文样例会在第 `1` 天就失败。
- **地图：** `R` 撞障碍，其余指令越界，最终仍是 `1 1`。`1×1` 空地图上所有移动都无效。
- **三种笔：** 三组结果依次为 `3`、`1`、`0`。`n = m = 0` 时，三种都不买也是一个方案。
- **两数之和：** 下标对有 `6` 个，不同数值组合只有 `{2, 2}` 一种。
- **购买：** 选 `2 2 3`，共 `3` 件，恰好花 `7`。全部四件需要 `12`，所以不能买 `4` 件。
- **活动：** 首尾可相接时可选 `[0, 2)`、`[2, 4)`、`[4, 5)`，共 `3` 场；要求严格晚于时最多 `2` 场，例如 `[0, 2)`、`[4, 5)`。
- **合并：** `1+2=3`，代价 `3`；再取 `3`、`3`，得到 `6`，累计 `9`；最后 `4+6=10`，总代价 `19`。一堆时为 `0`；四堆重量都是 `2` 时总代价为 `16`。
- **收益反例：** `[0, 2)` 收益 `1`，`[0, 3)` 收益 `100`。优先最早结束只能获得 `1`，选择后者则能获得 `100`。

</details>

**本篇你学到了：**

- 模拟先明确状态、初值和更新顺序，再逐步执行规则。
- 枚举要保证范围完整、检查正确，并按题意避免重数。
- 用约束减少变量，可以让直接枚举变得更高效。
- 贪心要说明当前选择为什么不会失去最优答案，交换论证是一种常见方法。
- 排序和堆可以帮助执行贪心，但选什么、为什么这样选，仍由题目决定。
- 反例、小数据枚举和对拍，能帮助检查直觉与代码；复杂度和边界也必须一起考虑。

做题时，先把最直接的办法写清楚。能模拟就先走一遍，能枚举就先列出来；如果想贪心，就认真问一句：**这一步选完以后，我凭什么还能走到最优答案？**
