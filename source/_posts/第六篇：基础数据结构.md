在第四篇里，我们学会了用数组存放一大批数据。在第五篇里，我们学会了用函数组织代码，也认识了递归。

到这里，你已经可以写出不少程序了。但如果题目换一种要求呢？

- 一份名单里，经常有人加入，也有人离开。
- 编辑器里，你希望撤销刚才的操作。
- 食堂窗口前，先来的人应该先取到饭。
- 一批任务里，每次都要先处理最紧急的那个。
- 一个文件夹下面，还有文件夹和文件。

这些问题当然都可以先拿一个数组试着写。但你很快会发现：**数据怎么存、按什么顺序取，会直接影响代码的写法和运行速度。**

这时候，我们就要开始认识**数据结构**了。

你可以把它理解成：**给数据安排一种组织方式，并规定我们怎样访问和修改它们。**

这一篇先认识六种基础结构：**顺序表、链表、栈、队列、树和堆**。我们从它们为什么有用讲起，再看 C++ 里怎么写。

> 本文的完整程序可以分别复制运行，使用 C++11 或更新的标准即可。代码里的普通数组和 `vector` 默认从 `0` 开始编号；模拟链表和树时会单独说明节点编号，堆的下标示意则从 `1` 开始。

------

### 零、先认识三个复杂度记号

后面会反复出现 `O(1)`、`O(n)` 和 `O(log n)`。如果你还没学过时间复杂度，先这样理解就够了：`n` 表示数据的规模，我们关心的是**数据变多以后，操作量怎样增长**。

| 记号 | 直观理解 | 例子 |
| --- | --- | --- |
| `O(1)` | 操作量不随数据规模增长 | 用下标访问一个数组元素 |
| `O(n)` | 最坏可能要处理与元素数量成正比的数据 | 从头到尾找一个数 |
| `O(log n)` | 操作量增长很慢 | 沿一棵高度约为 `log n` 的树上下移动 |

比如，直接访问 `a[500]`，不需要先读完 `a[0]` 到 `a[499]`。但如果要在一个没有排好序的数组里找值为 `500` 的元素，就可能要检查整个数组。

**按位置访问，和按值查找，是两种不同的操作。** 这个区别，后面还会遇到很多次。

------

### 一、顺序表：把数据放在连续的一排盒子里

#### 1. 先认识线性表

假设有一份名单：

```plaintext
小明 → 小红 → 小李 → 小王
```

我们关心的是：谁在第一个位置，谁在第二个位置，谁排在谁前面。像这样，元素之间有一条明确的先后关系，就可以看成一张**线性表**。

这里的“先后”指位置关系，**并不要求元素按大小排序**。`8, 3, 10, 1` 一样可以组成线性表。

线性表有不同的存储方式。把元素放进一块连续的内存，就是**顺序表**；后面要讲的链表，则使用另一种方式把元素连接起来。

#### 2. 顺序表和数组有什么关系？

数组是实现顺序表的一种常见工具。除了数组本身，我们通常还要记录**当前实际有多少个元素**。

比如开了 `int a[100]`，只存入三个数：

```plaintext
下标：   0    1    2    3    4   ...   99
数据：  10   20   30   空   空   ...   空
有效长度：n = 3
```

数组容量是 `100`，有效长度是 `3`。后面的空位还没有成为表里的元素。

顺序表最大的优点，是**可以通过下标直接访问元素**。知道位置就能直接找到对应的盒子，时间复杂度为 `O(1)`。

#### 3. 为什么中间插入和删除比较慢？

如果要把 `15` 插到 `10` 和 `20` 之间：

```plaintext
插入前：10  20  30
先后移：10  空  20  30
插入后：10  15  20  30
```

为了保持连续存储，后面的元素要向右挪。删除中间的元素也一样，后面的元素要向左补上空位。

所以，**顺序表在中间插入、删除，最坏需要 `O(n)` 的时间**。自己用数组实现插入时，要从后往前移动，避免把还没搬走的数据覆盖掉。

#### 4. C++ 里的 `vector`：可以自动扩容的顺序表

第四篇里提到过 `vector`。现在我们把它拿出来用一用。你可以把它理解成一个**容量不够时会自动扩大的数组**。

下面是一个完整程序：

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> a = {10, 20, 30};

    a.push_back(40);                  // 在末尾加入 40
    a.insert(a.begin() + 1, 15);      // 在下标 1 的位置插入 15
    a.erase(a.begin() + 2);           // 删除此时下标 2 的元素，也就是 20
    a.pop_back();                    // 删除末尾的 40

    cout << a[0] << endl;             // 输出 10
    cout << a.size() << endl;         // 输出 3

    for (int x : a) {
        cout << x << " ";             // 输出 10 15 30
    }
    cout << endl;
    return 0;
}
```

这里的 `vector<int>` 表示“存放整数的动态数组”；`a.begin()` 表示第一个元素的位置，`a.begin() + 1` 就是往后一个位置。这个位置对象叫**迭代器**，目前先把它当作标准库识别元素位置的工具。

`for (int x : a)` 是一种遍历写法，意思是“依次取出 `a` 中的每一个元素，把值放到 `x` 里”。如果只是修改 `x`，不会修改原来的元素。

常用操作可以先记下来：

| 操作 | 含义 | 复杂度 |
| --- | --- | --- |
| `a[i]` | 访问下标为 `i` 的元素 | `O(1)` |
| `a.size()` / `a.empty()` | 获取元素数量 / 判断是否为空 | `O(1)` |
| `a.push_back(x)` | 在末尾加入元素 | 均摊 `O(1)` |
| `a.pop_back()` | 删除末尾元素 | `O(1)`，要求非空 |
| `a.insert(...)` / `a.erase(...)` | 在指定位置插入 / 删除 | 最坏 `O(n)` |

“均摊 `O(1)`”怎么理解？多数追加只需要放一个元素，但偶尔容量不够，会分配更大的空间并搬走已有元素，这一次可能花 `O(n)` 的时间。**把一长串追加操作的成本平均下来，每次仍是常数级别。**

> **注意：`size()` 是已经存在的元素数量，`capacity()` 是当前容量。** `vector<int> a;` 此时没有元素，不能直接写 `a[0] = 5`。即使调用了 `a.reserve(100)`，也只是预留空间，长度仍是 `0`；想创建 100 个元素，可以写 `vector<int> a(100)`。

如果题目需要按下标访问，或者主要在末尾追加数据，顺序表通常很合适。

### 二、链表：盒子不必挨着，用连接关系串起来

顺序表插入一个元素，需要给它腾位置。能不能让原来的元素不用搬家呢？

可以。让每个元素除了存自己的值，再记住“下一个元素在哪里”：

```plaintext
head → [10 | next] → [20 | next] → [30 | 空]
```

这样就形成了**链表**。

你可以把它想象成一列火车。每节车厢是一个**节点**，里面装着数据，连接装置把它和下一节车厢串起来。节点在内存里不必连续，先后顺序由连接关系决定。

#### 1. 插入和删除为什么方便？

原来是：

```plaintext
A → B
```

把新节点 `X` 放在 `A` 后面，只需要改成：

```plaintext
A → X → B
```

删除 `X` 时，再让 `A` 直接连接 `B` 就行。其他节点不用移动。

但这里有一个重要前提：**你已经知道要修改的位置。**

如果题目只告诉你“删除第 500 个元素”，单链表通常得从头一步一步走过去。链表不能像数组一样，通过下标直接跳到逻辑上的第 500 个位置。

因此，对单链表来说，**已知前驱节点后的插入、删除是 `O(1)`；查找位置或值，最坏是 `O(n)`。** “前驱”就是排在当前节点前面的那个节点。

#### 2. 在竞赛里，用数组模拟单链表

真正的链表可以使用指针来连接节点。为了先把结构理解清楚，我们用**数组下标充当节点编号**：

- `e[k]`：编号为 `k` 的节点存放的值。
- `ne[k]`：这个节点的下一个节点编号。
- `-1`：后面没有节点了。
- `idx`：下一个可以使用的节点编号。

下面额外使用编号 `0` 作为**哨兵头节点**。它不存有效数据，只负责指向第一个真正的节点。有了它，表头插入和普通插入就可以用同一套写法。

```cpp
#include <iostream>
using namespace std;

const int N = 100005;
int e[N], ne[N];
int idx = 1;                         // 0 留给哨兵头节点

// 在节点 k 后面插入 x，返回新节点编号；容量不足返回 -1
// 调用前保证 k 是哨兵头节点，或当前链表中存在的节点
int insert_after(int k, int x) {
    if (idx >= N) {
        return -1;
    }
    int node = idx;
    idx ++;
    e[node] = x;
    ne[node] = ne[k];                 // 新节点先接上原来的后继
    ne[k] = node;                     // k 再指向新节点
    return node;
}

// 删除节点 k 后面的节点；调用前同样保证 k 合法
bool erase_after(int k) {
    if (ne[k] == -1) {
        return false;                // 后面没有节点，不能删
    }
    ne[k] = ne[ne[k]];                // 跳过待删除节点
    return true;
}

int main() {
    ne[0] = -1;                      // 初始化为空表

    insert_after(0, 30);
    insert_after(0, 20);
    int first = insert_after(0, 10);  // 现在是 10 → 20 → 30
    int middle = insert_after(first, 15);
    erase_after(middle);             // 删除 15 后面的 20

    for (int i = ne[0]; i != -1; i = ne[i]) {
        cout << e[i] << " ";          // 输出 10 15 30
    }
    cout << endl;
    return 0;
}
```

插入时最关键的是这两句的顺序：

```plaintext
ne[新节点] = ne[k]   先记住原来后面的节点
ne[k] = 新节点       再把新节点接进去
```

如果反过来写，就会丢掉原来的连接关系，还可能让新节点指向自己。

还有一点：**节点编号不等于它在链表中的位置。** 上面编号 `1` 的节点存的是 `30`，它最后排在第三个位置。遍历链表靠的是 `ne[i]`，不能直接用 `i ++`。

> 这个简化实现删除节点后，只修改连接关系，不回收节点编号。因此数组容量要按**累计插入次数**准备，而不是只看当前链表长度。删除后的编号也不能继续当作有效节点使用。多组数据需要重新设置 `ne[0] = -1` 和 `idx = 1`。

#### 3. 还有哪些链表？

**单链表**只记录下一个节点。**双向链表**再记录前一个节点，可以向两个方向移动，已知节点时也更容易把它摘掉。**循环链表**则让末尾重新连接到开头。

C++ 标准库里的 `list` 是双向链表，`forward_list` 是单链表。它们适合通过迭代器操作节点，不能写 `list[i]` 来随机访问。

链表擅长的是“已知位置以后改连接”，顺序表擅长的是“按位置直接访问”。选哪一个，要看题目到底经常做哪种操作。

### 三、栈：像一摞盘子，后放进去的先拿出来

假设桌上有一摞盘子，你把盘子一个一个放上去，也从最上面一个一个拿下来。

最后放上去的，最先被拿走。这就是**栈**的规则：**后进先出**，英文是 `LIFO`（Last In, First Out）。

```plaintext
依次压入 10、20、30：

    ┌────┐
    │ 30 │ ← 栈顶：只能从这里加入或取出
    ├────┤
    │ 20 │
    ├────┤
    │ 10 │ ← 栈底
    └────┘

依次弹出：30、20、10
```

向栈里加入元素叫**入栈 / 压栈**，删除栈顶元素叫**出栈 / 弹栈**。

#### 1. 用数组模拟栈

既然只操作一端，一个数组加一个长度就够了。下面用 `tt` 表示栈里有多少个元素，栈顶下标就是 `tt - 1`。

```cpp
#include <iostream>
using namespace std;

int main() {
    const int N = 100;
    int stk[N];
    int tt = 0;                      // tt = 0 表示空栈

    stk[tt ++] = 10;
    stk[tt ++] = 20;
    stk[tt ++] = 30;                  // 入栈前要保证 tt < N

    while (tt > 0) {
        cout << stk[tt - 1] << " ";   // 查看栈顶
        tt --;                       // 弹出栈顶
    }
    cout << endl;                    // 输出 30 20 10
    return 0;
}
```

`stk[tt ++] = x` 的意思是先把 `x` 放在当前空位，再把长度加一。出栈时不必清零数组，缩短有效长度就行。

数组模拟栈的入栈、出栈和取栈顶都是 `O(1)`。

#### 2. C++ 里的 `stack`

如果题目没有要求手写，可以直接用标准库：

```cpp
#include <iostream>
#include <stack>
using namespace std;

int main() {
    stack<int> s;
    s.push(10);
    s.push(20);
    s.push(30);

    while (!s.empty()) {
        int x = s.top();             // 先读取栈顶
        s.pop();                     // 再删除栈顶
        cout << x << " ";            // 输出 30 20 10
    }
    cout << endl;
    return 0;
}
```

| 操作 | 含义 |
| --- | --- |
| `s.push(x)` | 压入一个元素 |
| `s.pop()` | 删除栈顶元素 |
| `s.top()` | 读取栈顶元素 |
| `s.empty()` | 判断是否为空 |
| `s.size()` | 获取元素数量 |

`stack<int>` 默认底层使用 `deque`，上述操作都是 `O(1)`。

> **注意：`pop()` 不返回被删除的元素。** 如果想用那个值，就先 `top()`，再 `pop()`。栈为空时，不能调用 `top()` 或 `pop()`。

#### 3. 栈可以用来做什么？

**撤销操作**很适合栈：最近一次操作先撤销，之后再撤销更早的操作。

**括号匹配**也很适合。遇到左括号就入栈，遇到右括号就看栈顶能不能和它配对。因为右括号应该优先匹配最近一个还没匹配的左括号。

上一篇的递归其实也用到了这个规则：函数一层层调用，最后进入的那一层先返回，这就是**调用栈**。

### 四、队列：像排队取餐，先来的人先走

栈是从同一端加入和取出。队列则是另一套规则：**从队尾加入，从队头取出**。

想想食堂排队：先来的人站在前面，后来的站到最后。先排到队里的人，先得到处理。

这叫**先进先出**，英文是 `FIFO`（First In, First Out）。

```plaintext
出队 ← [10] [20] [30] ← 入队
        队头      队尾

依次入队：10、20、30
依次出队：10、20、30
```

#### 1. 用数组模拟队列

用 `hh` 记录队头位置，用 `tt` 记录下一次入队的位置。有效元素放在 `[hh, tt)` 这个区间里，也就是包含 `hh`，不包含 `tt`。

```cpp
#include <iostream>
using namespace std;

int main() {
    const int N = 100;
    int q[N];
    int hh = 0, tt = 0;

    q[tt ++] = 10;
    q[tt ++] = 20;
    q[tt ++] = 30;                   // 入队前要保证 tt < N

    while (hh < tt) {
        cout << q[hh] << " ";        // 查看队头
        hh ++;                      // 弹出队头
    }
    cout << endl;                   // 输出 10 20 30
    return 0;
}
```

判空条件是 `hh == tt`，当前长度是 `tt - hh`。入队、出队和访问队头都是 `O(1)`，出队时不用把所有元素向前移动。

不过这个版本的队头和队尾只会向右走，**不会重复利用前面已经空出来的位置**。如果不断入队、出队，即使当前队列很短，也可能把数组用完。因此容量要按累计入队次数准备。

想反复利用空间，可以使用**循环队列**：下标走到末尾后，通过取余绕回开头，同时记录元素数量来区分空队和满队。刚入门时先理解普通队列，再考虑这种实现。

#### 2. C++ 里的 `queue`

```cpp
#include <iostream>
#include <queue>
using namespace std;

int main() {
    queue<int> q;
    q.push(10);
    q.push(20);
    q.push(30);

    cout << q.back() << endl;        // 输出 30：查看队尾

    while (!q.empty()) {
        int x = q.front();          // 读取队头
        q.pop();                    // 删除队头
        cout << x << " ";           // 输出 10 20 30
    }
    cout << endl;
    return 0;
}
```

| 操作 | 含义 |
| --- | --- |
| `q.push(x)` | 在队尾加入元素 |
| `q.pop()` | 删除队头元素 |
| `q.front()` / `q.back()` | 读取队头 / 队尾 |
| `q.empty()` / `q.size()` | 判断是否为空 / 获取元素数量 |

默认底层同样使用 `deque`，这些操作都是 `O(1)`。`pop()` 同样不返回值，访问或删除元素前也要保证队列非空。

队列适合按到达顺序处理任务。后面学**广度优先搜索（BFS）**时，我们还会用它保存等待处理的节点，一层一层地向外扩展。

#### 3. 顺便认识双端队列 `deque`

普通队列只从队尾入、队头出。如果两头都允许加入和删除，就是**双端队列**。

```cpp
#include <iostream>
#include <deque>
using namespace std;

int main() {
    deque<int> d;
    d.push_back(20);                 // 尾部加入 20
    d.push_front(10);                // 头部加入 10
    d.push_back(30);                 // 尾部加入 30

    cout << d.front() << " " << d.back() << endl; // 输出 10 30
    d.pop_front();
    d.pop_back();
    cout << d[0] << endl;            // 输出 20
    return 0;
}
```

`deque` 两端的插入、删除和下标访问是 `O(1)`，中间插入、删除最坏是 `O(n)`。它支持下标访问，但不像 `vector` 那样保证所有元素位于同一块连续内存里。

### 五、树：数据之间不再只有一条线

前面的结构，都在处理一条线上的数据。如果要存一个文件目录呢？

```plaintext
学习资料
├── 算法竞赛
│   ├── 语法
│   └── 数据结构
└── 工程
    ├── 命令行
    └── 浏览器
```

一个目录下面可以有多个子目录，子目录下面还可以继续分。数据之间出现了**层次和分支**，这就适合用**树**来表示。

#### 1. 几个基础概念

从图论的角度说，树是**连通且没有环的无向图**。在竞赛里，我们经常选一个节点作为根，把它看成有层次的**有根树**。

先看这棵树：

```plaintext
        1
       / \
      2   3
     / \
    4   5
```

- **节点**：图里的 `1` 到 `5`，每个节点可以保存数据。
- **边**：连接两个节点的线。
- **根节点**：我们选作起点的节点，这里是 `1`。
- **父节点 / 子节点**：`1` 是 `2`、`3` 的父节点，`2`、`3` 是 `1` 的子节点。
- **兄弟节点**：拥有同一个父节点，比如 `4` 和 `5`。
- **叶子节点**：没有子节点的节点，这里是 `3`、`4`、`5`。
- **子树**：一个节点和它下面的所有后代，比如以 `2` 为根的子树包含 `2`、`4`、`5`。

有 `n` 个节点的树有 `n - 1` 条边，任意两个节点之间有且只有一条简单路径。选根以后，除根外，每个节点恰好有一个父节点。

“深度”和“高度”有按边数、按节点数计数的不同习惯。**本文按边数计数**：根的深度是 `0`，往下一条边加 `1`；树的高度是根到最远叶子的边数。上面这棵树的高度为 `2`。

#### 2. 二叉树：每个节点最多有两个孩子

**二叉树**里的每个节点最多有两个孩子，分别叫左孩子和右孩子。上面的例子就是一棵二叉树。

“最多两个”不是“必须两个”，左孩子和右孩子的位置也要区分。只有一个左孩子，和只有一个右孩子，是不同的结构。

两种常见形态可以先认识：

- **满二叉树**：本文采用常见教材定义，每层都填满，所有叶子在同一层，非叶子节点都有两个孩子。
- **完全二叉树**：除最后一层外都填满，最后一层的节点从左往右连续排列，中间不能留空。

注意，“完全”描述的是形状，和节点里的值大小没有关系。下一节的二叉堆，就建立在完全二叉树上。

#### 3. 用数组保存左右孩子

为了先理解结构，我们用节点编号来存树：`lc[u]` 表示节点 `u` 的左孩子，`rc[u]` 表示右孩子，`0` 表示没有孩子。下面真实节点从 `1` 开始编号，并直接把编号作为要输出的数据。

遍历，就是把所有节点按某种顺序访问一遍。二叉树常见的三种顺序是：

| 遍历 | 访问顺序 | 上面那棵树的结果 |
| --- | --- | --- |
| 前序遍历 | 根 → 左子树 → 右子树 | `1 2 4 5 3` |
| 中序遍历 | 左子树 → 根 → 右子树 | `4 2 5 1 3` |
| 后序遍历 | 左子树 → 右子树 → 根 | `4 5 2 3 1` |

这正好可以用上一篇的递归来写：**处理一棵树，就是处理根节点，再以同样的方法处理它的子树。**

```cpp
#include <iostream>
#include <queue>
using namespace std;

const int N = 10;
int lc[N], rc[N];                    // 全局数组初始为 0

void preorder(int u) {
    if (u == 0) return;              // 空节点：递归终止条件
    cout << u << " ";
    preorder(lc[u]);
    preorder(rc[u]);
}

void inorder(int u) {
    if (u == 0) return;
    inorder(lc[u]);
    cout << u << " ";
    inorder(rc[u]);
}

void postorder(int u) {
    if (u == 0) return;
    postorder(lc[u]);
    postorder(rc[u]);
    cout << u << " ";
}

void levelorder(int root) {
    if (root == 0) return;
    queue<int> q;
    q.push(root);

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        cout << u << " ";
        if (lc[u] != 0) q.push(lc[u]);
        if (rc[u] != 0) q.push(rc[u]);
    }
}

int main() {
    lc[1] = 2;
    rc[1] = 3;
    lc[2] = 4;
    rc[2] = 5;

    preorder(1);
    cout << endl;                    // 1 2 4 5 3
    inorder(1);
    cout << endl;                    // 4 2 5 1 3
    postorder(1);
    cout << endl;                    // 4 5 2 3 1
    levelorder(1);
    cout << endl;                    // 1 2 3 4 5
    return 0;
}
```

前三个函数只改变“输出当前节点”这句话的位置，遍历顺序就变了。**前、中、后，说的都是根节点在左、右子树之间什么时候被访问。**

最后的 `levelorder` 是**层序遍历**。它借助队列，让根先进入队列，处理一个节点后，把它的孩子排到队尾，因此上一层会先于下一层被处理。

这些遍历都只访问每个节点一次，时间复杂度是 `O(n)`。递归遍历额外需要 `O(h)` 的调用栈空间，`h` 为树高；层序遍历的队列空间最坏是 `O(n)`。这里不计保存树本身的空间。

> **树不一定很矮。** 如果每个节点都只有一个孩子，树会长成一条链，高度为 `n - 1`。这种树递归层数可能很深，不能因为代码短就忽略调用栈限制；数据很大时可以用显式栈或队列遍历。

#### 4. 二叉树不等于二叉搜索树

普通二叉树只规定每个节点最多有两个孩子，**不保证左边的值小、右边的值大**。

如果再规定“左子树里的值都小于根，右子树里的值都大于根”（先不考虑重复值），就得到**二叉搜索树**。这类树的中序遍历才会得到递增序列。

普通二叉树的中序遍历没有这个保证；普通二叉搜索树也不自动保证平衡，查找耗时与树高有关，最坏可能是 `O(n)`。先记住这两个区别，就不容易把不同的树混在一起。

### 六、堆：每次都想快速拿到最大的或最小的

假设有一批任务，每个任务都有一个紧急程度。新任务不断加入，你每次都要取出当前最紧急的任务。

用普通数组，每次扫描找最大值要 `O(n)`。把数组排好序也能取到最值，但新任务来了，又要维护排序。

如果我们只关心“谁最紧急”，有没有一种结构，既方便加入，也方便取出最值？

这就是**堆**。这里先讲最常见的**二叉堆**。

#### 1. 二叉堆有两个要求

第一个要求是形状：它是一棵**完全二叉树**。

第二个要求是值的关系：

- **大根堆**：每个父节点的值都不小于它的孩子，根是整个堆的最大值。
- **小根堆**：每个父节点的值都不大于它的孩子，根是整个堆的最小值。

比如下面是一棵小根堆：

```plaintext
        1
       / \
      3   2
     / \
    8   5
```

`1` 不大于 `3`、`2`，`3` 不大于 `8`、`5`，所以它满足要求。

但你会发现：**兄弟节点之间没有要求，左子树和右子树之间也没有整体的大小关系。** `3` 可以比 `2` 大，`8` 也可以比 `5` 大。

因此，堆保证的是**根为最值，以及每条父子边上的大小关系**。直接按存储顺序读出堆里的元素，不会得到完整的排序结果。

#### 2. 为什么堆通常用数组保存？

完全二叉树从上到下、从左到右编号后，节点之间的位置关系非常整齐。如果从 `1` 开始存：

```plaintext
节点 i 的父节点：i / 2（整数除法，i > 1）
节点 i 的左孩子：2 * i
节点 i 的右孩子：2 * i + 1
```

上面的小根堆就可以存成：

```plaintext
下标：1  2  3  4  5
数据：1  3  2  8  5
```

判断有没有孩子时，还要检查孩子下标是否超过当前元素数量。如果改成从 `0` 开始存，下标公式也要相应改变，不能混用。

这里也能看出：**一种结构的逻辑关系，和它实际使用什么容器保存，是两个层面的事情。** 堆在逻辑上是一棵树，实现时却可以只用数组。

#### 3. 插入和删除最值怎样维护？

以小根堆为例：

**插入**时，先把新元素放到最后一个位置，保证完全二叉树的形状。如果它比父节点小，就交换，继续向上比较，这叫**上浮**。

**删除最小值**时，先把最后一个元素搬到根，再删除最后一个位置。如果新的根比孩子大，就和**较小的那个孩子**交换，继续向下比较，这叫**下沉**。

为什么选较小的孩子？比如当前节点是 `8`，两个孩子是 `3` 和 `2`，必须让 `2` 上来。如果让 `3` 上来，父节点 `3` 仍大于另一个孩子 `2`，堆的条件就还没恢复。

完全二叉树的高度是 `O(log n)`，上浮、下沉最多沿着一条路径移动，所以插入和删除堆顶都是 `O(log n)`。**只查看堆顶，不改变结构，则是 `O(1)`。**

#### 4. C++ 里的 `priority_queue`

堆经常用来实现**优先队列**：按照优先级取元素，而不是按照入队先后取元素。C++ 提供了 `priority_queue`，默认使用大根堆。

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <functional>
using namespace std;

int main() {
    priority_queue<int> big;                         // 大根堆
    priority_queue<int, vector<int>, greater<int>> small; // 小根堆

    for (int x : {3, 1, 4, 1, 5}) {
        big.push(x);
        small.push(x);
    }

    while (!big.empty()) {
        cout << big.top() << " ";                    // 输出 5 4 3 1 1
        big.pop();
    }
    cout << endl;

    while (!small.empty()) {
        cout << small.top() << " ";                  // 输出 1 1 3 4 5
        small.pop();
    }
    cout << endl;
    return 0;
}
```

小根堆的声明看起来比较长，可以先按三部分理解：`int` 是元素类型，`vector<int>` 是底层容器，`greater<int>` 是比较规则，它让较小的元素出现在堆顶。

| 操作 | 含义 | 复杂度 |
| --- | --- | --- |
| `heap.top()` | 读取堆顶 | `O(1)` |
| `heap.push(x)` | 插入元素并维护堆 | 均摊 `O(log n)` |
| `heap.pop()` | 删除堆顶并维护堆 | `O(log n)` |
| `heap.empty()` / `heap.size()` | 判断是否为空 / 获取元素数量 | `O(1)` |

这里插入写“均摊”，是因为默认底层的 `vector` 偶尔会扩容搬移元素；**堆调整本身**最多是 `O(log n)`。空堆不能调用 `top()` 或 `pop()`，`pop()` 也不返回值。

**重复元素可以同时存在。** 上面的两个 `1` 都会被保存，不会因为值相同就合并。

如果反复弹出所有堆顶，确实会得到有序序列，但要进行多次堆调整，总时间是 `O(n log n)`。如果只要找一次最值，扫描一遍数组就够了；堆更适合数据不断变化、又要反复取最值的场景。

> **这里的“堆”和内存管理中的“堆区”不是同一个概念。** 本节讲的是数据结构二叉堆；第五篇提到的调用栈，则是程序执行时保存函数调用信息的机制。

### 七、放在一起看：题目需要什么，就选什么

先把这些结构的特点放到一张表里：

| 结构 | 最重要的特点 | 基本操作或限制 | 典型需求 |
| --- | --- | --- | --- |
| 顺序表 | 连续存储，按下标访问 | 下标访问 `O(1)`；中间插删最坏 `O(n)` | 名单、批量数据、按位置访问 |
| 单链表 | 通过连接关系组织节点 | 已知前驱后插删 `O(1)`；查找最坏 `O(n)` | 已知节点附近频繁插删 |
| 栈 | 后进先出 | 只操作栈顶，基本操作 `O(1)` | 撤销、括号匹配、保存待返回状态 |
| 队列 | 先进先出 | 队尾入、队头出，基本操作 `O(1)` | 排队处理、层序遍历 |
| 树 | 表达层次和分支 | 完整遍历 `O(n)`；其他操作取决于树的种类和高度 | 目录、上下级关系 |
| 二叉堆 | 完全二叉树，加上父子大小规则 | 查看最值 `O(1)`；调整路径 `O(log n)` | 动态加入任务、反复取最值 |

表里的栈、队列复杂度对应本文的数组实现或默认标准库实现；堆这一行的调整成本不包含底层动态数组偶发的扩容成本。

顺序表和链表提供了不同的存储方式；栈、队列强调的是**允许怎样操作，以及取出的顺序**。所以你可以用数组实现栈，也可以用链表实现栈。它们的名字不在同一个分类维度上，彼此也不是互斥的。

刚开始做题时，先问自己：**我最经常做的操作是什么？**

需要按下标取数据，就先考虑数组或 `vector`；需要拿出最近放进去的东西，就考虑栈；需要按到达顺序处理，就考虑队列；需要表达父子关系，就考虑树；需要不断取出当前最值，就考虑堆。

### 八、常见错误与注意事项

#### 1. 空容器还在取元素

`s.top()`、`q.front()`、`heap.top()` 都要求容器非空，`pop()` 也一样。先判断 `empty()`，再读取和删除。

`vector` 和 `deque` 的 `front()`、`back()`、`pop_back()` 等也有非空要求。数组模拟时，要自己检查长度和容量。

#### 2. 以为删除操作会把值返回来

`stack`、`queue`、`priority_queue` 的 `pop()` 返回类型是 `void`。需要那个值时，**先保存，再删除**，不能写 `int x = s.pop()`。

#### 3. 把队列和优先队列混在一起

普通队列按进入顺序取元素，优先队列按优先级取元素。名字里都有“队列”，出队规则却不同。

对于 `int`，默认的 `priority_queue<int>` 取最大值；需要最小值时，记得使用小根堆的声明。

#### 4. 以为链表只要插入删除就一定更快

如果每次都要从头寻找目标位置，查找的时间仍然是 `O(n)`。还要考虑额外的连接信息、内存访问方式和实现成本，不能只看“改连接是 `O(1)`”就认定链表一定合适。

#### 5. 把所有树的操作都当作 `O(log n)`

完全二叉树很矮，但普通树可能是一条长链。说一个操作是 `O(log n)`，要先确认对应树的高度和操作过程确实有这个保证。

#### 6. 多组数据忘记清空

如果容器定义在每组数据的局部作用域，会随这一组结束而销毁。如果复用全局数组或容器，就要主动重置长度、队头队尾、链表头和节点分配位置；树的左右孩子信息也要清理。

## 最后，去练习吧

这一篇先练基本操作。下面六个小练习都可以自己写程序验证，不需要先学其他算法：

1. **顺序表**：输入 `n` 个数，再输入一个下标 `pos` 和一个值 `x`，把 `x` 插入到 `pos` 前，输出结果。约定 `0 <= pos <= n`，`pos == n` 时追加到末尾。
2. **链表**：用数组模拟单链表，依次在表头插入 `1`、`2`、`3`，输出应为 `3 2 1`；再删除第一个有效节点，输出应为 `2 1`。
3. **栈**：输入一个只包含 `(`、`)` 的字符串，判断括号是否匹配。遇到右括号时如果栈为空，应立即判错；结束时栈也必须为空。`(())()` 应合法，`)(` 和 `(()` 应不合法。
4. **队列**：依次加入 `1`、`2`、`3`，取出一个，再加入 `4`，最后依次取出剩余元素，结果应为 `2 3 4`。同样的操作用栈做一遍，比较结果。
5. **树**：在本文的示例树中，让 `3` 的右孩子为 `6`，分别写出四种遍历结果，再运行程序核对。
6. **堆**：支持两种操作：“加入一个整数”和“取出当前最小值”。遇到空堆时输出 `EMPTY`；先加入 `3`、`1`，取出一次，再加入 `2`，继续取出，结果应依次为 `1`、`2`、`3`。

**本篇你学到了：**

- 顺序表用连续空间保存数据，`vector` 可以自动扩容。
- 链表用连接关系组织节点，已知位置后的插入、删除不需要移动其他元素。
- 栈后进先出，队列先进先出，双端队列允许操作两端。
- 树表达层次关系，二叉树可以用递归和队列遍历。
- 堆维护父子之间的大小关系，适合动态维护最大值或最小值。
- 选数据结构，要看题目需要的操作、数据范围和边界条件。

现在，把这些小练习敲一遍，让代码真正跑起来。每做一次加入、删除和访问，都看一眼数据的顺序怎样变化。理解了这些变化，后面的算法才有地方落脚。
